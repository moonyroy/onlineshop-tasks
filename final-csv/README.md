# خروجی نهایی مشتری‌ها

این فایل نسخهٔ خلاصه و قابل‌ارائهٔ نتیجهٔ پروژه است. هر ردیف مربوط به یک مشتریه و فقط ستون‌هایی رو نگه داشتیم که برای فهم وضعیت و تصمیم پیگیری لازم‌اند. فایل **۴٬۳۷۲ مشتری یکتا و ۹ ستون** داره.

برای خوندنش اول وضعیت و گروه مشتری رو ببین، بعد سطح خطر و اولویت رو و در آخر اقدام پیشنهادی رو بخون.

| ستون | توضیح ساده |
|---|---|
| `CustomerID` | شناسهٔ مشتریه. هر مشتری فقط یک ردیف داره. |
| `customer_status` | می‌گه مشتری فعاله، غیر فعاله، تازه‌وارده یا خرید مثبت کافی برای بررسی نداره. |
| `segment_name` | گروه رفتاری مشتریه، یعنی معمولاً چه‌جوری خرید کرده. شماره یا اسم گروه، درجهٔ خطر نیست. |
| `risk_level` | سطح خطر برآوردشدهٔ ریزشه. برای مشتری غیر فعال یا بدون سابقه، وضعیت جدا نوشته شده. |
| `risk_probability` | احتمال مدل برای توقف یا افت خرید طبق تعریف پروژه در افق ۱۰۰روزه است. مثلاً ۰٫۶ یعنی ۶۰ درصد. این عدد تضمین اتفاق‌افتادن ریزش نیست. |
| `priority_level` | می‌گه پیگیری مشتری چه اولویتی داره، مثل پایش، پیگیری معمولی یا پیگیری ویژه. برای غیر فعال‌ها مسیر بازگشت جدا داریم. |
| `risk_reason` | چند نشانهٔ رفتاری مثل فاصله از آخرین خرید و تعداد فاکتورها رو خلاصه می‌کنه. علت قطعی ریزش یا توضیح دقیق محاسبهٔ احتمال نیست. |
| `suggested_action` | پیشنهاد اولیه برای پیگیریه. تیم بازاریابی باید هزینه، امکان اجرا و شرایط تماس رو بررسی کنه. |
| `recommended_product_name` | محصول مرتبطی که بر اساس قواعد خرید پیشنهاد شده. اگر خالیه، پیشنهاد واجد شرایط پیدا نکردیم یا سابقه کافی نبوده. |

## هر ستون چه مقدارهایی می‌گیره؟

مقدارهای متنی پایین همون عبارت‌های داخل CSV هستن. برای ستون‌های عددی یا متن آزاد، به‌جای فهرست همهٔ مقدارها، شکل مقدار و معنی‌ش رو توضیح دادم.

### CustomerID

یک عددِ شناسه مثل `12360` می‌گیره. عدد بزرگ‌تر معنی ارزش یا خطر بیشتر نداره. توی این خروجی خالی نیست و تکرار هم نداره.

### customer_status

| مقدار | منظورمون چیه؟ |
|---|---|
| `فعال با سابقهٔ تکرار` | در ۱۲۰ روز آخر خرید داشته، از اولین خرید دیده‌شده‌اش حداقل ۳۰ روز گذشته و بیشتر از یک فاکتور داره. |
| `فعال با یک فاکتور` | در ۱۲۰ روز آخر خرید داشته، حداقل ۳۰ روز سابقهٔ دیده‌شده داره ولی فقط یک فاکتور ثبت شده. |
| `تازه‌وارد با سابقهٔ کوتاه` | خرید اخیر داره و از اولین خرید دیده‌شده‌اش کمتر از ۳۰ روز گذشته. ممکنه همین مدت چند فاکتور داشته باشه. |
| `غیر فعال` | خرید مثبت داره، ولی در ۱۲۰ روز آخرِ زمان بررسی خرید نکرده. این یعنی نیاز به بررسی برای بازگشت، نه اثبات رفتن همیشگی. |
| `فاقد خرید مثبت قابل‌تحلیل` | شناسه موجوده ولی خریدی با تعداد و قیمت مثبت و فاکتور غیرلغو براش نداریم. |

### segment_name

این ستون اسم گروهی رو می‌گیره که مدل خوشه‌بندی به مشتری نسبت داده. در اجرای فعلی این مقدارها رو داریم:

| مقدار | منظورمون چیه؟ |
|---|---|
| `کم‌فعالیت و دور از آخرین خرید — گروه 0` | نام توصیفی گروهیه که میانگین فاصله از خریدش بالا بوده و شرط نام‌گذاری گروه کم‌فعالیت رو گرفته. همهٔ اعضا الزاماً غیر فعال نیستن. |
| `لغو و مرجوعی بیشتر — گروه 1` | این گروه با شرط میانگین نرخ لغو بیشتر از ۱۲٪ نام‌گذاری شده. اسم گروه به معنی مرجوعی زیادِ تک‌تک اعضا نیست. |
| `لغو و مرجوعی بیشتر — گروه 2` | گروه رفتاری جداگانه‌ایه که همون شرط نام‌گذاری رو گرفته. داشتن اسم مشابه یعنی دو خوشه یکی نیستن و شماره فقط شناسهٔ گروه است. |
| `سابقهٔ مثبت کافی برای خوشه‌بندی ندارد` | برای این مشتری خرید مثبت قابل‌تحلیل نداریم و گروه عددی تعیین نکردیم. |

اسم‌ها مربوط به همین اجرای مدل‌اند و با آموزش دوباره ممکنه عوض بشن. از اسم گروه به‌تنهایی دربارهٔ سطح خطر تصمیم نمی‌گیریم.

### risk_probability و risk_level

`risk_probability` یک عدد از صفر تا یک، یا مقدار خالی می‌گیره. مثلاً `0.65` یعنی مدل برای تعریف ریزش پروژه احتمال ۶۵٪ داده. عدد موجود در فایل فعلی تقریباً بین `0.249` و `0.724` است. این بازهٔ نتیجهٔ فعلیه، نه محدودیت احتمالی مدل.

| مقدار risk_level | معنی یا بازهٔ احتمال |
|---|---|
| `بسیار کم` | از صفر تا کمتر از ۰٫۲، یعنی کمتر از ۲۰٪. |
| `کم` | از ۰٫۲ تا کمتر از ۰٫۴، یعنی ۲۰٪ تا کمتر از ۴۰٪. |
| `متوسط` | از ۰٫۴ تا کمتر از ۰٫۶، یعنی ۴۰٪ تا کمتر از ۶۰٪. |
| `زیاد` | از ۰٫۶ تا کمتر از ۰٫۸، یعنی ۶۰٪ تا کمتر از ۸۰٪. |
| `بسیار زیاد` | از ۰٫۸ تا یک، یعنی ۸۰٪ تا ۱۰۰٪. |
| `غیر فعال — خارج از جامعهٔ مدل` | مشتری مسیر بازگشت جدا داره و احتمال این طبقه‌بند براش خالیه. |
| `قابل‌امتیازدهی نیست` | خرید مثبت قابل‌تحلیل نداریم و احتمال براش خالیه. |

در فایل فعلی فقط سطح‌های کم، متوسط و زیاد عضو دارن. دو سطح دیگه حذف نشده‌اند، احتمال هیچ مشتری در بازهٔ اون‌ها نیفتاده. احتمال خالی رو صفر حساب نمی‌کنیم.

### priority_level

| مقدار | منظورمون چیه؟ |
|---|---|
| `پایش` | خطر کم یا بسیار کمه و فعلاً پیگیری پرهزینه پیشنهاد نشده. |
| `پیگیری معمولی` | خطر متوسطه و یادآوری یا بررسی کم‌هزینه می‌تونه مطرح بشه. |
| `پیگیری بالا` | خطر زیاد یا بسیار زیاده، ولی شرط پیگیری ویژه برقرار نشده. |
| `پیگیری ویژه` | احتمال حداقل ۶۰٪ است و برآورد درآمد آینده در یک‌چهارم بالای مشتری‌های دارای خرید مثبت قرار گرفته. |
| `بازگشت مشتری غیر فعال` | مشتری غیر فعاله و باید در مسیر بازگشت بررسی بشه. این مقدار یکی از درجه‌های احتمال ریزش نیست. |
| `بازبینی داده` | برای امتیازدادن سابقهٔ خرید مثبت نداریم و اول باید اسنادش بررسی بشن. |

این اولویت‌ها قواعد پیشنهادی پروژه‌اند و بودجهٔ واقعی یا اثر تماس رو ثابت نمی‌کنن.

### risk_reason

متن آزاد و کوتاهه، نه یک فهرست چندحالتی. معمولاً تعداد روز از آخرین خرید، تعداد فاکتور و نسبت ردیف مرجوعی رو می‌گه. مثلاً «آخرین خرید ۲۰ روز قبل، ۴ فاکتور، نسبت ردیف مرجوعی ۲٪». برای فرد بدون خرید مثبت، می‌گه سابقهٔ قابل‌تحلیل وجود نداره. این‌ها نشانهٔ مشاهده‌ای‌اند و علت قطعی ریزش نیستن.

### suggested_action

در این نسخه، متن اقدام یکی از این شش حالت است:

| عبارت داخل فایل | ساده‌ترش یعنی چی؟ |
|---|---|
| `بررسی برای کمپین بازگشت خارج از امتیاز پیشگیری` | مشتری غیر فعاله و پیشنهاد می‌کنیم برای بازگشت بررسی بشه. |
| `بررسی سابقهٔ لغو/مرجوعی توسط خدمات مشتری بدون فرض علت قطعی` | اول اسناد لغو و مرجوعی بررسی بشن. این قاعده وقتی نرخ لغو فرد بیشتر از ۱۲٪ باشه، قبل از پیشنهاد تخفیف یا یادآوری اعمال می‌شه. |
| `بررسی شخصی و پیشنهاد مرتبط هزینه و کانال نیازمند بررسی تیم بازاریابی` | مشتری اولویت ویژه داره و بررسی فردی پیشنهاد شده. |
| `یادآوری کم‌هزینه و بررسی پیشنهاد محصول مرتبط` | احتمال حداقل ۴۰٪ است و شرط اقدام قبلی برقرار نشده. |
| `حفظ ارتباط معمول بدون پیشنهاد پرهزینهٔ خودکار` | برای مشتری کم‌خطر، ارتباط معمول پیشنهاد شده. |
| `بررسی اسناد برگشت/اصلاح احتمال خطر ساختگی محاسبه نشده` | خرید مثبت نداریم و قبل از تصمیم بازاریابی باید اسناد بررسی بشن. |

پس ممکنه مشتری اولویت ویژه داشته باشه، ولی اقدام اولش بررسی خدمات مشتری باشه. دلیلش اینه که قاعدهٔ بررسی لغو جلوتر از قاعدهٔ پیشنهاد ویژه اجرا می‌شه.

### recommended_product_name

نام انگلیسی یک محصول رو می‌گیره، مثل `HEART OF WICKER LARGE`، یا خالی می‌مونه. در اجرای فعلی ۴۰ نام محصول متفاوت پیشنهاد شده. محصول پیشنهادی از قاعده‌ای اومده که با کالاهای خریداری‌شدهٔ مشتری منطبقه و خود محصول قبلاً در خریدهای ثبت‌شده‌اش نبوده.

خالی‌بودن این ستون یعنی قاعدهٔ واجد شرایط پیدا نکردیم یا سابقه کافی نبوده. نه اینکه مشتری هیچ محصول مناسبی نداره یا نباید پیگیری بشه.

## چند نکته برای برداشت درست

- احتمال خالی یعنی برای اون مشتری امتیاز محاسبه نشده، نه اینکه خطرش صفره.
- سطح خطر با اولویت یکی نیست. برای اولویت، ارزش احتمالی خرید آینده هم در کنار خطر در نظر گرفته شده.
- پنج سطح خطر بازه‌های ثابت دارن و لازم نیست همهٔ سطح‌ها عضو داشته باشن.
- تاریخ بررسی **۹ دسامبر ۲۰۱۱** است. مدل تاریخی به این تاریخ منتقل شده و رفتار بعد از پایان فایل در دسترس نیست، پس ارزیابی آیندهٔ این فهرست رو نداریم.
- تازه‌واردها سابقهٔ کوتاه‌تری دارن و نتیجه‌شون باید با احتیاط بیشتری خونده بشه. برآورد ارزش آینده هم محدودیت‌های مدل خرید رو داره.
- اقدام‌ها پیشنهاد آموزشی‌اند. هنوز با اجرای کمپین ثابت نکردیم که باعث حفظ مشتری می‌شن.
