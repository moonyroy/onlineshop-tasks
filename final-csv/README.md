# راهنمای خوندن فایل نهایی مشتری‌ها

هر ردیف این فایل مربوط به یک مشتریه. برای شروع، وضعیت مشتری، گروه رفتاری، سطح خطر، اولویت و اقدام پیشنهادی رو کنار هم ببین. گروه رفتاری با درجهٔ خطر یکی نیست.

| ستون | توضیح ساده |
|---|---|
| `CustomerID` | شناسهٔ مشتریه. هر شناسه توی این فایل فقط یک ردیف داره. |
| `snapshot_date` | تاریخ و ساعتیه که تا اون لحظه خریدها رو بررسی کردیم. |
| `risk_horizon_days` | خطر رو برای چند روز بعد برآورد کردیم. اینجا افق مدل ۱۰۰ روزه است. |
| `customer_status` | می‌گه مشتری فعاله، غیر فعاله، تازه‌وارده یا خرید مثبت کافی برای بررسی نداره. |
| `Country` | کشوریه که از اولین خرید مثبت ثبت‌شدهٔ مشتری گرفتیم. |
| `segment_id` | شمارهٔ گروه رفتاریه. بزرگ‌تر بودن شماره یعنی خطر بیشتر نیست. |
| `segment_name` | اسم گروهیه که بر اساس رفتار خرید مشتری بهش دادیم. |
| `risk_probability` | احتمالیه که مدل برای ریزش طبق تعریف پروژه داده. مثلاً ۰٫۶ یعنی ۶۰ درصد. احتمال خالی یعنی برای این مشتری امتیاز ندادیم، نه اینکه خطرش صفره. |
| `risk_level` | احتمال مدل رو به یکی از پنج سطح خطر تبدیل می‌کنه. برای مشتری غیر فعال یا بدون سابقه، وضعیت جدا نوشته شده. |
| `risk_reason` | چند نشانهٔ خرید مشتری رو خلاصه می‌کنه تا وضعیتش قابل‌فهم‌تر باشه. علت قطعی ریزش یا توضیح دقیق تصمیم مدل نیست. |
| `obs_invoices` | تعداد فاکتورهای خرید مثبت مشتری تا تاریخ بررسیه، نه تعداد ردیف‌های کالا. |
| `obs_spend` | جمع مبلغ خریدهای مثبت مشتریه. مرجوعی و لغوهای بعدی کامل با سفارش اصلی تطبیق داده نشده‌اند، پس این عدد فروش خالص یا سود نیست. |
| `obs_recency` | می‌گه از آخرین خرید مثبت مشتری چند روز گذشته. |
| `obs_tenure` | می‌گه از اولین خرید مثبت دیده‌شدهٔ مشتری چند روز گذشته. لزوماً تاریخ شروع واقعی رابطه با فروشگاه نیست. |
| `cancel_rate` | سهم فاکتورهای لغو از مجموع فاکتورهای خرید مثبت و لغوه. به‌تنهایی دلیل نارضایتی رو ثابت نمی‌کنه. |
| `return_rate` | سهم ردیف‌هایی با تعداد منفی از ردیف‌های ثبت‌شدهٔ مشتریه. درصد مبلغ برگشتی نیست. |
| `anomaly_score` | امتیاز متفاوت‌بودن رفتار مشتریه. عدد بالاتر یعنی رفتار غیرعادی‌تر، نه لزوماً مشتری بد یا پرخطرتر. |
| `anomaly_review` | اگر True باشه، مشتری بین ۱۰۰ مورد اول برای بررسی رفتار غیرعادی قرار گرفته. این فقط علامت بازبینیه، نه دستور حذف. |
| `expected_purchase_days_100d` | مدل انتظار داره مشتری در ۱۰۰ روز بعد چند نوبت خرید روزانه داشته باشه. خریدهای یک روز رو یک نوبت گرفتیم و عدد اعشاری هم طبیعیه. |
| `expected_daily_basket_value` | مبلغ موردانتظار یک نوبت خرید روزانه است. سود یا مبلغ قطعی سفارش بعدی نیست. |
| `expected_revenue_100d` | برآورد مبلغ خرید مثبت در ۱۰۰ روز آینده است. تضمین درآمد یا ارزش کل عمر مشتری نیست. |
| `p_alive` | احتمال فعال‌بودن مشتری تحت فرض‌های مدل BG/NBD است و با احتمال ریزش CART یکی نیست. برای مشتری بدون خرید تکراری، این مدل عدد ۱ می‌ده که نشانهٔ اطمینان قطعی نیست. |
| `value_basis` | می‌گه برآورد مبلغ از سابقهٔ خرید تکراری فرد کمک گرفته یا از الگوی جمعیتی مدل. repeat_history یعنی سابقهٔ تکرار و population_prior یعنی الگوی جمعیتی. |
| `value_warning` | نکته‌هایی که موقع خواندن برآورد ارزش باید حواسمون بهشون باشه اینجا نوشته شده. |
| `priority_score` | امتیاز نسبی پیگیریه که خطر و رتبهٔ ارزش آینده رو کنار هم می‌ذاره. عدد بالاتر یعنی اولویت بیشتر، نه زیان مالی قطعی. |
| `priority_rank` | رتبهٔ پیگیری مشتری‌های امتیازگرفته است. عدد کوچک‌تر یعنی اولویت بیشتر و رتبهٔ مساوی هم ممکنه. |
| `priority_level` | اولویت رو با عبارت ساده مثل پایش، پیگیری معمولی یا پیگیری ویژه نشون می‌ده. غیر فعال‌ها مسیر بازگشت جدا دارن. |
| `suggested_action` | پیشنهاد اولیه برای پیگیری مشتریه. تیم بازاریابی باید امکان اجرا و هزینه‌اش رو بررسی کنه و اثرش هنوز آزمایش نشده. |
| `recommended_product_code` | کد محصول پیشنهادی بر اساس یک قاعدهٔ خرید منطبق با سابقهٔ مشتریه. این محصول قبلاً در خریدهای ثبت‌شده‌اش نبوده. خالی یعنی پیشنهاد واجد شرایط پیدا نکردیم. |
| `recommended_product_name` | نام همون محصول پیشنهادی رو نشون می‌ده. |
| `offer_basis` | می‌گه پیشنهاد از قاعدهٔ گروه مشتری اومده یا قاعدهٔ عمومی. اگر پیشنهاد نداریم، علتش مثل نبود قاعدهٔ منطبق یا سابقهٔ ناکافی نوشته شده. |
| `target_definition` | یادآوری می‌کنه ریزش رو در این پروژه چطور تعریف کردیم، یعنی توقف یا افت خرید طبق قرارداد مرحلهٔ آماده‌سازی. |
| `scoring_warning` | محدودیت‌های امتیاز خطر اینجا اومده، مثل کوتاه‌بودن سابقه یا انتقال مدل به آخرین تاریخ فایل. |

خالی‌بودن احتمال یا ارزش رو صفر حساب نکن. آخرین تاریخ داده ۹ دسامبر ۲۰۱۱ است و رفتار بعد از اون رو نداریم، پس امتیازها و پیشنهادها برای بررسی‌اند و نتیجهٔ قطعی آینده نیستند.
